# 《Token燃烧模拟器》首版游戏设计

## 1. 产品定位

《Token燃烧模拟器》是一款面向休闲用户的十分钟轻策略 Roguelike。它借用现代 Coding Agent 的 IDE、聊天、终端和代码 Diff 语言，让玩家直观体验：模型能力不是无限的，每一次重新读取仓库、生成补丁和运行测试，都在消耗上下文、时间和真实可换算的 API 费用。

核心幻想不是“成为最会写代码的人”，而是“在 Agent 不完全可靠的情况下，做一个会控制证据、成本和风险的程序员”。

## 2. 设计支柱

### 看起来专业，操作起来轻松

界面呈现文件树、编辑器、Agent 对话、终端和 Token 明细，但玩家不需要真正编写代码。所有输入都是中等粒度操作卡，单次决策能立即理解。

### 模糊预测，准确结算

操作前只给出 Token 区间、费用区间、速度和风险等级。执行后显示准确的输入、缓存命中、输出 Token 与人民币费用。玩家面对的是受控不确定性，而不是精确算术题。

### 证据对抗自信

调查、代码和验证是三条不同进度。只做实现就交付虽然更快，但隐藏风险仍然存在；日志、测试和自审能够降低风险。模型越强，平均进度和可靠度越高，但高价模型仍可能失败。

### 失败要短，重开要有理由

每局约十分钟。失败后可沿同一随机种子完整重试一次，便于验证刚才的策略是否真的更好；之后必须生成新路线。局外只提供内容解锁，不永久堆高初始资源。

## 3. 一局结构

路线共有七层：

1. 三选一开局项目。
2. 两条项目分支。
3. 项目或随机事件。
4. 中期项目。
5. 项目或上下文休整。
6. 最后一个常规项目。
7. 共同终点“周五 17:59 的发布”。

一条典型路线包含五个项目、一个随机事件、一个休整节点。更贪心的路径可能包含额外项目，奖励更多，但资源压力也更高。

## 4. 资源系统

| 资源 | 初始值 | 主要消耗 | 归零结果 |
| --- | ---: | --- | --- |
| API 预算 | ¥9.60 | 模型输入、缓存、输出 Token | 财务终止项目 |
| 上下文预算 | 180K | 读取文件、输出代码、测试结果 | Agent 遗忘任务 |
| Deadline | 58 格 | 每张操作卡、事件选择 | 客户取消项目 |
| 代码稳定度 | 78% | 高风险修改、失败交付、随机事件 | main 分支崩溃 |

项目成功返还 2 格 Deadline，形成小型节奏奖励。上下文不会在项目间自动清空，玩家必须使用压缩卡、缓存 Buff 或休整节点管理长期累积。

## 5. 项目遭遇

每个项目包含：简短需求、程序员笑话、代码文件、修改前后片段、测试命令、三项进度要求、隐藏风险数量和基础奖励。

玩家可以随时查看源码、Diff 和终端。首次进入时 Diff 为空；执行实现类操作后显示修改。测试类操作自动切换到终端输出。

交付概率由以下部分共同决定：

- 调查、实现、验证相对项目要求的完成度；
- 当前模型可靠度与能力；
- 提示词 Linter 等 Buff；
- 当前代码稳定度；
- 尚未通过调查、测试和自审消除的隐藏风险。

界面不显示百分比，只显示“很稳、可交付、有风险、危险、像在许愿”。实际结果由固定种子的伪随机序列决定，因此重试同一路线时，相同决策能够复现。

## 6. 操作卡

操作卡分为四类：

- 调查：扫描仓库、追踪日志、先写计划、查官方文档。
- 实现：精准补丁、整段重写、人工热修。
- 验证：针对性测试、完整回归、Agent 自审。
- 控制：压缩上下文、Git 回滚。

卡牌带有 1–3 次行动冷却，避免玩家连续点击同一种最优操作。人工热修不消耗 Token，但需要更多时间；整段重写推进最快，但稳定度和幻觉风险最高；压缩上下文会丢失一部分调查进度。

## 7. 模型与费用

Agent 外壳与后端模型分离。Codax 和 Cloude 决定界面措辞与视觉风格，GBT、DeepSick、Gloom、Gemina、Qwan 和 Cloude Sonnet 等决定能力、可靠度、速度和实际计价。

所有模型价格均来自 2026-09-10 官方公开页快照。执行时先根据当前上下文和缓存 Buff 计算缓存命中比例，再分别计算未缓存输入、缓存输入和输出费用。折扣 Buff 最后乘在调用总费用上。

游戏为了保持十分钟节奏，统一使用 Agent 工作区的 180K 初始上下文预算；价格图鉴仍展示现实模型的上下文说明。该预算是玩法参数，不冒充厂商接口上限。

## 8. 成长与奖励

每次项目成功后提供三项候选奖励，通常包含一个新模型和两个 Buff。新模型立即接入并自动切换；Buff 可能降低后续调用费用、提高缓存命中、增加可靠度、扩展上下文或提供免费 CI。

局外 XP 等于完成项目数，胜利额外获得 3 XP。XP 永久解锁更多开局模型，但不会增加预算、时间或稳定度。这样保留成长反馈，同时避免早期关卡因永久数值膨胀而失去意义。

## 9. 视觉与交互

- 真实 IDE 三栏：文件树 / 编辑器与任务 / Agent 与卡牌。
- 路线图使用细线、节点呼吸光和低密度网格，避免脱离开发工具语境。
- Codax 采用绿色强调色，Cloude 采用暖橙色强调色。
- 浅色与深色主题拥有独立变量，不是简单颜色反转。
- 声音使用离线可用的 Web Audio 合成：低音量终端氛围循环，以及点击、模型切换、Token 消耗、成功、风险和奖励提示音。
- 动效用于表达操作结果而非纯装饰：模型热切换、卡牌下压、消息入场、成功闪光与风险震屏；玩家可以随时精简动态效果。
- 首发面向桌面浏览器，1280px 以上获得完整布局；主页可响应到手机尺寸，实际对局保持 1024px 最小工作区。

## 10. 首版完成标准

- 从主页进入新 Run，能够选择三条起始路线。
- 所有节点状态、分支边和已完成路线正确更新。
- 至少能通过合理策略从初始模型抵达并击败最终 Boss。
- 费用公式、缓存折扣和限时 Buff 有自动测试。
- 主题、外壳、局外成长和活动 Run 能够持久化。
- 价格图鉴包含现实映射、原始价格、人民币换算、快照日期和官方来源。
- 构建、引擎测试和实际浏览器全流程均通过，无页面错误和横向溢出。
